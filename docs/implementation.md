# First implementation

## Implemented surface

Packaging and optional framework adapters are described in [framework setup](frameworks.md).
The BenchExec probe does not replace this runner. The OpenEvolve bridge evaluates
already frozen artifacts and does not implement candidate generation or promotion.

`schemas/experiment.schema.json` pins target/build identity, public workloads, isolation, search settings, cost limits, acceptance thresholds, sealed evaluation references, and evidence destination. `schemas/result.schema.json` validates individual exploration trials. Cross-field budget constraints are checked by `Policy` in addition to JSON Schema.

Workloads now select exactly one oracle mode: `expected_stdout_hash`, or `oracle` with kind `worldgame_ocean_v1`, `policy_path`, and `policy_hash`. The structured policy follows `schemas/ocean-oracle.schema.json`; `examples/worldgame-ocean-oracle.json` records the current pilot contract. Store the policy outside the target rootfs and protect it from candidate-agent writes. The runner checks the policy hash before execution and records structured results in `verification.json`. Timing diagnostics are parsed separately from the conservation and convergence gates. These checks do not independently validate scientific fields or prevent an implementation from printing fabricated summaries; a trusted independent oracle is still needed before optimization acceptance.

Oracle kind `worldgame_fields_v1` additionally compares strict numerical field streams against owner-pinned reference arrays using `schemas/field-oracle.schema.json`. The reference stays outside the target rootfs and is hash-checked before execution. A trusted driver reads library arrays rather than accepting the candidate benchmark's self-reported summaries. See the [field verification adapter](../verification/worldgame/README.md) for public-world and independently calculated manufactured-solution checks, the portable component kit, and remaining scientific coverage limits. This adapter is portable-tested; its native sandbox execution remains unvalidated.

`python -m chilicrisp.runner trial MANIFEST --workload ID --budget BYTES` runs one public trial. `python -m chilicrisp.controller MANIFEST` first takes repeated baseline runs with target `memory.max=max`, derives a page-aligned ceiling from the largest measured peak plus a margin, and then drives a per-workload frontier. Ancestor and host limits still apply and are recorded; this is not infinite host memory. Optional `baseline` settings default to three runs and a 10% margin. Baseline failures or missing peaks stop the experiment; baseline invocations count against the per-workload trial cap and experiment deadline. The derived starting limit must pass confirmation before descent. This controller cannot edit code, run hidden grading, or declare a production win. Sealed references and acceptance thresholds are reserved inputs for independent evaluation; this release does not implement those services. Builds are supplied as frozen rootfs artifacts, rather than executed by this runner.

## Linux prerequisites and preparation

Use a disposable Linux research VM. Install bubblewrap >= 0.12.0, libseccomp, Python 3.12+, and the Python requirements. The minimum bubblewrap version addresses [the upstream rootfs setup advisory](https://github.com/containers/bubblewrap/security/advisories/GHSA-pxhw-h44j-8pfx). The runner refuses root execution and requires unprivileged user namespaces plus a delegated cgroup v2 parent with memory and pids subtree controllers already enabled. It requires `cgroup.kill`, swap accounting, memory peak counters, and readable ancestor settings. Provision delegation outside the target; the program does not grant itself privileges.

Prepare a minimal, frozen rootfs with the target runtime and executable, and real `proc`, `dev`, and `tmp` directories. Do not bind the host root or copy credentials into it. The pilot syscall allowlist intentionally excludes process/thread creation and networking, so targets needing them are outside this initial adapter. Rootfs files and evidence must be protected from the candidate agent by the experiment owner. Hash checks detect changes but do not replace filesystem access control or an atomic artifact store.

For fixture validation, copy `tests/workload.py` to `/fixtures/workload.py` within that rootfs and supply `/usr/bin/python3` with its runtime dependencies. Copy `examples/experiment.json` to an owner-controlled location; replace source/build identity and all host paths. Create an empty public input file. Compute the rootfs hash using `python -m chilicrisp.runner hash-rootfs ROOTFS`. The rootfs hash includes file paths, modes, symlink targets, and file contents. Freeze the rootfs before and throughout trial execution.

Set `CHILI_FIXTURE_MANIFEST` to that fixture manifest on Linux and run `python -m unittest discover -s tests -v`. The native tests cover normal output, wrong output, timeout, output flooding, OOM, and an injected cleanup failure followed by recovery. They intentionally fail if preflight returns unsupported, rather than counting an unsupported sandbox as a fixture success.

## Enforcement and lifecycle

The launcher enters the fresh cgroup in the forked child before executing bubblewrap or any workload code. This is the documented fallback to `clone3`; early Python fork/launcher residency and shared inherited pages remain accounting qualifications. Whole-program measurements include sandbox/runtime overhead and cannot be described as component-only usage.

Bubblewrap supplies separate namespaces, a read-only controlled root, an isolated network namespace, a bounded scratch tmpfs, no capabilities, and a libseccomp default-deny filter. Target code has no cgroup filesystem, host secrets, hidden inputs, or writable evidence mounts. The input is read-only stdin. Scratch writes, process count, descriptors, core files, and stdout/stderr are bounded. `/dev` is remounted read-only. The kernel remains shared: this is a pilot policy requiring native validation, not a security certification.

Each trial journals `CREATED → PREFLIGHT_VALIDATED → CGROUP_CONFIGURED → RUNNING → TERMINATING → COLLECTING → FINALIZED`. Failure enters termination and collection; cleanup or evidence-persistence failure ends in `RECOVERY_REQUIRED`. Cleanup is attempted independently of lifecycle writes. Original errors are retained alongside finalization errors. If ordinary result persistence fails, a separate low-level `emergency.json` diagnostic is attempted; if that storage also fails, the caller receives the error in memory. No implementation can guarantee persistence on unavailable storage. Emergency diagnostics are not validated successful trial records. A new trial refuses an evidence directory containing unfinished journals or unrecovered emergency diagnostics. Run only one controller per evidence directory and delegated parent; concurrent scheduling is not supported.

After verifying no controller still owns an interrupted trial, explicitly recover its journal with `python -m chilicrisp.recovery JOURNAL --cgroup-parent PARENT`. If initial journaling failed, the command also accepts `emergency.json`. Recovery validates the exact parent and trial name, kills only that trial's cgroup, and records the interrupted measurement as invalid. Do not recover an active peer's trial. Sudden controller death can leave incomplete raw data; the journal allows cleanup, not reconstruction of nonexistent measurements.

## Reference search and output policy

The example defaults are 25% initial reduction, at most 50% reduction, geometric midpoint refinement, 5% bracket tolerance, ten trials per selected point, and thirty trials per workload including baseline invocations. Two fully confirmed passing points permit the maximum reduction. Mixed outcomes at a point exhaust that point's confirmation count and terminate as inconclusive. A timeout stops with `latency_pressure_requires_diagnosis` and is retained in a separate performance-pressure list; it does not establish an OOM boundary. All-passing descent stops at the minimum or available resolution with no invention claim. `INVENT` requires observed passing and OOM-failing points. This conservative reference implementation does not yet implement neighboring-grid noise estimation. Every point is screened once, then confirmed; it favors reproducibility over maximum search speed. The controller owns the decision and a hard experiment wall budget; no agent-supplied precision requests are executed.

Output is permitted only as the declared required stdout result and bounded diagnostic stderr. Each stream is drained incrementally to a capped evidence file and hashed; exceeding its limit signals termination and yields `output_limit`. A candidate cannot read either pipe back as temporary state. The reader stops at the first oversized chunk rather than continuing to hash a flood. Truncated outputs explicitly identify their hash as a retained-prefix hash and their byte count as bytes observed before reading stopped, not total bytes produced. Verification uses the frozen workload's selected exact-hash or structured comparator and requires successful exit. Neither mode alone establishes independent physical accuracy.

## Verification status and limitations

Portable checks cover schema rejection, search caps and noise, controller stop decisions, lifecycle persistence, unfinished-run blocking, unsupported-host evidence, and a real output-flood subprocess. Native cgroup OOM, seccomp, namespace isolation, kernel counters, and process-tree cleanup require the Linux fixture run. Docker and WSL access were denied in the current Windows session.

There is no hidden-set lifecycle service, randomized transplant evaluator, candidate generation, or production acceptance yet. Automatic baseline selection is implemented and tested using injected measurements; native baseline collection remains unvalidated on Linux. Model costs stay unavailable unless supplied by a future orchestrator. Artifact hashing and preflight add controller time; trial elapsed time is recorded separately. These limits keep current capabilities distinguishable from the complete research protocol.
